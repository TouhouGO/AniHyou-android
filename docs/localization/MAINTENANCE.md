## 资源数据更新

`Refresh catalog sources` 每周一 03:17 UTC（马来西亚时间 11:17）或手动运行。
它刷新并固定 bangumi-data、soruly 和完整 Wikidata 标签/身份查询快照，在临时目录
完成格式、冲突、数量和可复现性检查后，提交独立审阅分支并创建 PR。

单类记录或 Wikidata 原始证据减少超过 10%、旧身份冲突被解除、来源失败/空响应/
达到查询上限都会阻止自动提升。维护者应调查原因，必要时通过有证据的人工更新
处理，不能仅为了跑通流程而放宽保护。内容不变不创建新版本；同日内容变化延到
下个 UTC 日期。版本是目录版本，不是 APK 版本。

目录 PR 合并后，`Publish catalog` 会自动发布独立 JSON 通道：

- 不可变日期版本：`catalog-vYYYY.MM.DD/catalog.json`，附许可证与来源说明。
- 客户端指针：`catalog-latest/catalog-manifest.json`，包含确切版本、大小与 SHA-256。
- 先上传并公开验证日期版本，再更新指针；同版本不同内容、降级和验证失败拒绝发布。
- JSON 通道与其他资源独立；发布时不修改无关资源。

更新已有 GitHub release asset 时存在短暂缺口；客户端失败会保留当前目录，发布脚本
在上传失败时尝试恢复旧指针。详细协议和限制见 [CATALOG_UPDATES.md](CATALOG_UPDATES.md)。

## 应用内部行为

自动检查默认开启，保存设置加载后才生效。应用进入前台且到期时异步检查：成功后
间隔 24 小时，失败或频道未就绪后间隔 1 小时。不会阻塞启动，也不承诺应用完全
关闭时检查。设置页可关闭自动检查、查看上次检查、立即检查、手动下载、导入或恢复。

发现新版本时主界面提示进入设置；不会静默下载或安装。安装先检查来源引用、
schema、日期版本、大小和哈希，再事务写入；错误保留旧目录。目录更新不改变
AniList 原始模型、缓存、收藏状态或账号数据。
