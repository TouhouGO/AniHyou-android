# 汉化重设计的架构取舍

本实现以 `axiel7/AniHyou-android` 为官方来源，保留上游版权和许可。此前方案的
HTTP 拦截器同时处理标题、简介、标签、人物、字形转换和搜索；拆分这些职责可
降低网络响应、搜索和缓存之间的耦合。

## 结论与取舍

旧方案中的本地索引、别名、繁简归一化、在线补充和缓存方向有价值。需要重设计的
主要部分是职责边界：在 HTTP 拦截器中同步改写 JSON，同时处理搜索、译名、外部
身份关联与缓存，使一个改动的影响范围难以预测。入口少并不代表整体维护成本低。

新方案保留 AniList 原始数据，在显示处解析译名，并把搜索和资源维护设为独立服务。
它更适合本项目目前的缓存、筛选、列表编辑和上游更新方式。没有证据可以声称它是
所有设备、数据规模和网络环境下的绝对最优解。

| 关注点 | 旧分支调查结果 | 新实现 |
| --- | --- | --- |
| 数据展示 | HTTP 响应统一重写，需处理缓存和后续模型复用 | 原始 Apollo 对象保留，显示函数按实体 ID 取译名 |
| 身份 | 数字标题键和部分名称回退缺少完整类型/来源上下文 | MEDIA、CHARACTER、STAFF 分离；未知媒体类型的别名仅参与候选查询 |
| 搜索速度 | 本地优先、阈值和缓存减少网络等待，但补充路径可能阻塞首批 | 后台不可变倒排索引；本地与补充结果独立推进 |
| 搜索覆盖 | 精确命中短路、少量结果阈值、硬编码特例可能改变召回 | 完整 exact/prefix/substring 候选；无固定关键字 ID；保留独立原文与在线补充 |
| 筛选分页 | 拦截层需推断 GraphQL 参数与搜索状态 | 显式 `id_in` 参数；所有 AniList 筛选复用同一请求映射 |
| 繁简 | 字符转换用于索引 | 固定 OpenCC 字符数据，旧 Android 字符表兼容；只折叠检索键 |
| 简介 | 多种关联和在线获取逻辑耦合 | 单独的可取消来源请求；仅显式同类型关联，失败保留原文 |
| 资源更新 | 多份资源和兼容路径扩大状态组合 | 单个版本化目录；校验、持久提交、快照发布串行处理 |
| 界面覆盖 | 通用拦截覆盖广，但模型语义不易区分 | 各显示入口显式接入；Widget、通知 Worker、Wear 独立加载 |

## 当前模块边界

`core/localization` 不依赖 Android 或 Apollo，负责目录格式、不可变快照、实体键、
检索别名、字符折叠和索引。名称相同不会生成跨平台身份关联；来源别名不会覆盖
已有显示译名。来源版本、哈希、许可声明和排除报告随可复现输入保留。

`core/network` 负责明确的 AniList 查询和独立的 Bangumi/目录更新 HTTP 客户端。
Bangumi 请求不携带 AniList 登录信息。网络失败、限流、格式不符与成功空结果有
不同处理；外部简介不写进 Apollo 或标题目录。

`core/domain` 管理目录生命周期、缓存、并发和更新事务。下载完成不等于启用成功；
持久提交后才发布快照。恢复内置目录会使先前下载令牌失效。新更新通道与旧分支
格式隔离，当前本地实现不等于已发布远端更新资源。

Compose 显示函数只接受原始 ID 和原文。标签的显示值与筛选键分离；动态、通知保留
结构化标题槽位，不对整段文字做替换。列表搜索使用完整候选 ID，中文显示开关不
改变查询本身的中文召回能力。

## 为什么暂不换数据库或引入统一转换模型

当前 12,492 个可检索媒体 ID 的后台内存索引可以处理一字、两字及子串查询，主机
P95 见 `SEARCH_PERFORMANCE.md`。引入 SQLite/FTS 需要额外验证短查询、平台支持、
数据库生成与升级；目前没有实测证据说明它能带来足够收益。接口保留以后替换索引
实现的余地，当前优先解决已测到的瓶颈和召回问题。

全面复制所有 Apollo 生成模型为本地化模型也会增加维护面。显示投影保留上游类型，
仅在组合文本和独立生命周期场景增加必要的结构化字段；不会为局部译名改写整个
网络数据层。

## 仍需用数据检验的部分

现有显示目录含 9,375 个媒体、3,103 个 STAFF、799 个 CHARACTER 和 426 个标签。
附加检索别名把媒体检索 ID 扩到 12,492 个，但不能把来源数量换算成准确率或完整
覆盖率。媒体类型不明的来源候选由 AniList 查询类型进一步筛选。被隔离的身份冲突
不会为凑覆盖数量而重新放行。

本地索引暖查询快，但首次解析/建索引有数百毫秒主机开销。设备内存、低端机首屏、
网络首结果及完整补充时延仍未验证。现阶段没有操作模拟器或设备，也没有进行
生产签名、推送、部署或更新通道发布。最终产物说明应保留这些验证边界。
